# گزارشِ Veeam → کارتابل

سرورِ sltech بیرونِ شبکهٔ شماست و به پورتِ ۹۴۱۹ِ سرورِ Veeam نمی‌رسد.
می‌شد آن پورت را به اینترنت باز کرد، ولی برای یک جدولِ وضعیت بهای خیلی
گزافی است. پس جهت برعکس است: `veeam-push.ps1` روی یک ویندوزِ داخلِ
شبکه می‌نشیند، از REST APIِ خودِ Veeam می‌پرسد و خلاصه را می‌فرستد.
هیچ درگاهی باز نمی‌شود؛ ارتباط همیشه از داخل به بیرون است.

چه چیزی می‌رود: نامِ جاب، نوعش، نتیجهٔ آخرین اجرا، وضعیت، زمانِ آخرین و
بعدیِ اجرا، و تعدادِ آبجکت. نه خودِ بکاپ، نه نامِ کاربری، نه رمز.

> **چرا متنِ اسکریپت انگلیسی است؟** ویندوزپاورشلِ ۵.۱ فایلِ `.ps1` را با
> کدپیجِ ANSIِ سیستم می‌خواند، مگر فایل BOMِ یونیکد داشته باشد — و BOM
> اولین باری که کسی فایل را با Notepad ذخیره کند می‌پرد و اسکریپت با
> خطای پارس می‌افتد. اسکریپتی که روی سرورِ یک مشتری زندگی می‌کند نباید
> به این بند باشد، پس عمداً فقط ASCII دارد و راهنمایش این‌جاست.

---

## ۱) بخش را در پنل باز کنید

پنل → **کارتابل‌ها** → روی کارتابل، **ویرایش** → زیرِ «کدام بخش‌های خودِ
کارتابل را ببیند»، تیکِ **VeeamBackup** → **ذخیره**.

هر بخشِ تازه‌ای پیش‌فرض بسته است؛ بدونِ این تیک دکمه‌اش در نوار نمی‌آید.

## ۲) کلید بسازید

پنل → روی همان کارتابل، **کلید Veeam** → **کلید بساز**.

کلید و آدرسِ فرستادن را همان‌جا بردارید. کلید مثل رمزِ ورود درهم‌شده
ذخیره می‌شود، پس **فقط همین یک بار دیده می‌شود**. گم شد؟ یکی تازه
بسازید — همان لحظه قبلی از کار می‌افتد.

## ۳) در Veeam یک کاربرِ فقط‌خواندنی بسازید

کنسولِ Veeam → منوی اصلی → **Users and Roles** → **Add** → نقشِ
**Veeam Backup Viewer**.

کاربرِ ادمین لازم نیست و نباید داد: اسکریپت فقط می‌خواند. اگر روزی آن
ویندوز دستِ کسی بیفتد، چیزی بیشتر از «دیدنِ وضعیت» در دستش نیست.

مطمئن شوید سرویسِ REST APIِ Veeam روشن است و پورتِ ۹۴۱۹ روی خودِ سرورِ
Veeam از داخلِ شبکه در دسترس است.

## ۴) فایل‌ها را روی ویندوز بگذارید

پوشه: `C:\veeam-push\`

دو فایل کنارِ هم:
- `veeam-push.ps1`
- `veeam-push.config.json`

قالبِ فایلِ تنظیمات — `veeam-push.config.sample.json` را کپی و نامش را
`veeam-push.config.json` بگذارید:

```json
{
  "VbrHost": "veeam01.company.local",
  "VbrUser": "COMPANY\\veeam-viewer",
  "VbrPass": "...",
  "PushUrl": "https://sltech.ir/api/kartabl/veeam/push",
  "PushKey": "...",
  "SkipCertCheck": true
}
```

| کلید | چه بگذارید |
|---|---|
| `VbrHost` | نام یا IPِ سرورِ Veeam. خودش `https://` و `:9419` را اضافه می‌کند؛ اگر پورتتان فرق دارد کاملش را بنویسید: `https://10.0.0.5:9419` |
| `VbrUser` | کاربرِ قدم ۳. بک‌اسلش **دوتایی** — قاعدهٔ JSON است |
| `VbrPass` | رمزِ همان کاربر |
| `PushUrl` | آدرسی که در قدم ۲ گرفتید |
| `PushKey` | کلیدی که در قدم ۲ گرفتید |
| `SkipCertCheck` | `true` برای گواهیِ خودامضا (معمولاً همین)، `false` اگر گواهیِ معتبر دارید |

فایلِ تنظیمات را **UTF-8** ذخیره کنید و دسترسی‌اش را ببندید — رمزِ Veeam
داخلش است:

```
icacls C:\veeam-push\veeam-push.config.json /inheritance:r /grant SYSTEM:F /grant Administrators:F
```

اگر فایل را از اینترنت دانلود کرده‌اید، ویندوز ممکن است مسدودش کرده
باشد:

```
Unblock-File C:\veeam-push\veeam-push.ps1
```

## ۵) یک بار دستی اجرا کنید

```
powershell -NoProfile -ExecutionPolicy Bypass -File C:\veeam-push\veeam-push.ps1
```

| خروجی | یعنی |
|---|---|
| `Sent: 12 job(s)` | همه‌چیز درست است |
| `Sent, but Veeam errored: ...` | به کارتابل رسید ولی به Veeam نرسید — کاربر، رمز یا پورت را ببینید |
| `Push to kartabl failed: ...` | به sltech.ir نرسید — کلید یا دسترسیِ اینترنتِ آن ویندوز را ببینید |

وقتی خطایی از سمتِ Veeam آمد، `-Verbose` بزنید: برای هر نسخهٔ API، کدِ
وضعیت و **متنِ خودِ Veeam** را چاپ می‌کند — همان چیزی که می‌گوید اشکال از
رمز است یا از نسخه یا از MFA:

```
powershell -NoProfile -ExecutionPolicy Bypass -File C:\veeam-push\veeam-push.ps1 -Verbose
```

## ۶) ساعتی یک بار

در PowerShell با دسترسیِ Administrator:

```
schtasks /create /tn "Veeam report to kartabl" /sc hourly /ru SYSTEM ^
  /tr "powershell -NoProfile -ExecutionPolicy Bypass -File C:\veeam-push\veeam-push.ps1"
```

اجرای فوری برای تست:

```
schtasks /run /tn "Veeam report to kartabl"
```

## ۷) در کارتابل ببینید

کارتابل → **VeeamBackup** در نوارِ کنار.

**روی ردیف بزنید.** هر جاب یا اجرایی که Veeam درباره‌اش چیزی نوشته —
یا ماشینی داخلش دارد — کنارِ نتیجه‌اش یک ⓘ کوچک می‌گیرد و کلیک‌پذیر
می‌شود. با زدنش پنجره‌ای وسطِ صفحه باز می‌شود و دو چیز را نشان می‌دهد:

* **پیامِ Veeam** — همان جمله‌ای که خودِ Veeam دربارهٔ آخرین اجرا نوشته،
  دست‌نخورده و با همان شکستِ خط. همان چیزی که تا دیروز باید برای دیدنش
  می‌رفتید سرِ کنسولِ Veeam.
* **ماشین‌های داخلِ این جاب** — فهرستِ نامِ ماشین‌هایی که این جاب از
  آن‌ها بکاپ می‌گیرد.

با `Escape` یا زدن روی زمینهٔ تاریک بسته می‌شود. ردیفی که نه پیامی
دارد و نه ماشینی، اصلاً کلیک‌پذیر نیست.

> فهرستِ ماشین‌ها و پیامِ خطا از نسخهٔ تازهٔ همین اسکریپت می‌آیند. اگر
> در پنجره نوشت «فهرستِ ماشین‌ها نرسیده»، `veeam-push.ps1` روی سرورِ
> شما قدیمی است — فایلِ تازه را جایش بگذارید و یک بار دستی اجرا کنید.

## وقتی چیزی درست نیست

| چه می‌بینید | چه کار کنید |
|---|---|
| دکمهٔ VeeamBackup در نوار نیست | قدم ۱ انجام نشده |
| «هنوز هیچ گزارشی از Veeam نرسیده» | اسکریپت هنوز اجرا نشده یا به sltech.ir نمی‌رسد — قدم ۵ را دستی بزنید |
| هشدارِ زرد «این گزارش N دقیقه پیش آمده» | اسکریپت ایستاده — تاریخچه‌اش را در Task Scheduler ببینید |
| هشدارِ قرمز «اسکریپتِ فرستنده به Veeam نرسید» | متنِ خطا همان‌جا نوشته شده — ادامهٔ جدول |
| `HTTP 400` با `invalid_grant` یا «user name or password» | نام کاربری یا رمزِ Veeam. فرمِ درست: `DOMAIN\\user` در JSON (بک‌اسلشِ دوتایی) |
| `HTTP 400` و حرفی از MFA | آن کاربرِ Veeam احراز هویتِ دومرحله‌ای دارد. اسکریپت نمی‌تواند آن را رد کند؛ یک کاربرِ سرویسِ بدونِ MFA بسازید |
| `Unsupported RESTAPI version` | خودِ اسکریپت حلش می‌کند: Veeam در همان پیام می‌گوید کدام نسخه را قبول دارد و اسکریپت با همان دوباره تلاش می‌کند |
| در پانویسِ بخش نوشته `(via /jobs + sessions)` | مسیرِ وضعیتِ جاب‌ها جواب نداد، پس نتیجهٔ هر جاب از آخرین اجرایش درآمده. جدول کامل است |
| در پانویسِ بخش نوشته `(via /jobs)` | همان بالا، ولی اجرایی هم نبود که از آن نتیجه درآید — ستونِ «نتیجهٔ آخر» خالی می‌ماند |
| در پنجرهٔ ردیف نوشته «فهرستِ ماشین‌ها نرسیده» | `veeam-push.ps1` قدیمی است؛ فایلِ تازه را جایگزین کنید |
| در پنجرهٔ ردیف نوشته «Veeam پیامی ننوشته» | اشکالی نیست: Veeam برای اجرایی که بی‌حادثه تمام شده، چیزی نمی‌نویسد |
| `jobs/states -> HTTP 500` با `EJobStatus is not supported` | ایرادِ خودِ Veeam در این نسخهٔ API؛ از بیرون درست‌شدنی نیست. اسکریپت خودش دور می‌زند و نتیجه را از `sessions` می‌گیرد |
| `HTTP 401` | کاربر هست ولی نقشِ لازم را ندارد — `Veeam Backup Viewer` بدهید |
| `timeout` یا `No connection could be made` | پورتِ ۹۴۱۹ یا نامِ سرور در `VbrHost` |

در پنل، دکمهٔ **کلید Veeam** بالای دکمه‌ها می‌گوید آخرین گزارش کِی، از
کدام سرور و با چند جاب رسیده.

---

## دو تصمیمِ عمدی

**گزارشِ کهنه هشدار می‌گیرد.** اگر آخرین گزارش بیش از ۹۰ دقیقه پیش آمده
باشد، صفحه می‌گوید. اسکریپت ساعتی یک بار می‌فرستد، پس نیم ساعت تحمل
دارد. سبزِ سه روز پیش بدتر از هیچ است: آدم نگاه می‌کند، سبز می‌بیند و
خیالش راحت می‌شود.

**اگر به Veeam نرسد، باز هم می‌فرستد** — با متنِ خطا. نفرستادن یعنی
سکوت، و سکوت دقیقاً شبیهِ «همه‌چیز خوب است» دیده می‌شود.
