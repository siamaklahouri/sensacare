# جابه‌جاییِ sltech.ir از کلادفلر به سرورِ خودمان

`sensacare.ir` دست نمی‌خورد. روی همان ورکر می‌ماند، با همان دیتابیس.
این نوشته فقط دربارهٔ `sltech.ir` است.

## وضعِ امروز

| چیز | کجا |
|---|---|
| برنامه | `/opt/sltech/app` — سرویسِ `sltech`، پورت `8787`، کاربرِ `sltech` |
| تنظیمات | `/etc/sltech/env` |
| دیتابیس | `/var/lib/sltech/sltech.db` |
| nginx | `/etc/nginx/sites-available/sltech` |
| گواهی | `/etc/letsencrypt/live/new.sltech.ir/` |
| آدرسِ آزمایشی | `https://new.sltech.ir` → همین سرور |
| واسطِ تلگرام | `https://tg.sltech.ir` → ورکرِ `sltech-relay` |
| `sltech.ir` | هنوز رکوردِ Worker روی کلادفلر |

## چرا واسطِ تلگرام

از این سرور `api.telegram.org` باز نمی‌شود. پس:

* سایت → تلگرام: `https://tg.sltech.ir/tg/<SECRET>/bot<token>/<method>`
* تلگرام → سایت: `https://tg.sltech.ir/api/sl/bot/...` → `ORIGIN`

`ORIGIN` روی `https://new.sltech.ir` است و بعد از جابه‌جایی هم همان
می‌ماند: `new.sltech.ir` رکوردِ جداست و به همین سرور اشاره می‌کند، پس
مسیرِ ربات از تغییرِ `sltech.ir` اثر نمی‌گیرد.

## ترتیبِ کار

**۱ — بی‌آنکه کسی بفهمد**

* `git pull` و راه‌اندازیِ دوبارهٔ سرویس
* عوض کردنِ `RELAY_SECRET` (در گزارشِ قدیمی چاپ شده بود)
* نصبِ `backup.sh` با زمان‌سنجِ شبانه
* آزمونِ دوباره روی `new.sltech.ir`

**۲ — باز هم بی‌آنکه کسی بفهمد**

گواهیِ `new.sltech.ir` گسترش داده می‌شود تا `sltech.ir` و
`www.sltech.ir` را هم بپوشاند. این باید **پیش از** تغییرِ DNS انجام
شود، وگرنه بینِ تغییرِ رکورد و گرفتنِ گواهی چند دقیقه‌ای https برای
کاربرانِ واقعی می‌شکند.

روشِ فایلی (HTTP-01) این‌جا کار نمی‌کند، چون تا وقتی رکورد عوض نشده
`sltech.ir` به ورکر می‌رود نه به این سرور. پس روشِ DNS-01 با افزونهٔ
کلادفلرِ certbot — که یک توکنِ کلادفلر با دسترسیِ **Zone → DNS →
Edit** روی `sltech.ir` می‌خواهد.

**۳ — تنها قدمی که دیده می‌شود**

* `nginx-sltech.conf` جای فایلِ فعلی
* در کلادفلر: برداشتنِ دو رکوردِ Worker (`sltech.ir`, `www`) و گذاشتنِ
  دو رکوردِ `A` به `185.231.112.152`، **خاکستری** نه نارنجی
* ثبتِ دوبارهٔ webhook از راهِ واسط
* روشن کردنِ کرون (برداشتنِ `CRON_UTC=-`)

## برگشت

اگر چیزی خراب شد، برگشت یک کار است: در کلادفلر رکوردهای `A` را بردار و
دو رکوردِ Worker را بگذار. دیتابیس روی سرور مانده و ورکر همان دیتابیسِ
D1 را دارد — پس داده‌ای که بینِ این دو نوشته شده باشد از دست می‌رود.
برای همین پنجرهٔ بینِ این دو باید کوتاه باشد.
