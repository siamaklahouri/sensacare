# کاوشگرِ شبکه — راه‌اندازی

این اسکریپت **روی یک سیستمِ داخلِ شبکهٔ خودتان** اجرا می‌شود (هر ویندوزی که
به روتر و دستگاه‌ها می‌رسد — همان سیستمی که `veeam-push.ps1` رویش است هم
خوب است). رنجی که می‌گویید را می‌گردد، می‌فهمد هر نشانی چیست، شمارندهٔ
بایتِ هرچه SNMP دارد را می‌خواند، و همه را به کارتابل می‌فرستد.

**چرا این‌طوری:** سرورِ کارتابل بیرونِ شبکهٔ شماست و به `192.168.x.x`
نمی‌رسد. اگر بخواهد از بیرون اسکن کند، باید شبکه‌تان را به اینترنت باز
کنید — بهایی که برای یک جدولِ مصرف اصلاً نمی‌ارزد. این‌طوری هیچ پورتی باز
نمی‌شود: اتصال همیشه از داخل به بیرون است.

**هیچ رمزِ ویندوز یا دامینی لازم نیست.** اسکریپت از دستگاه‌های شبکه
می‌خواند، نه از کامپیوترها.

---

## ۱. کلید را بگیرید

در پنل مدیر → کارتابلِ همان شخص → «کلیدِ کاوشگرِ شبکه» → «کلیدِ تازه».
کلید **فقط همان یک بار** نشان داده می‌شود؛ جایی امنش کنید. اگر گم شد،
یکی تازه بسازید و همان لحظه قبلی از کار می‌افتد.

## ۲. دو فایل را کنار هم بگذارید

مثلاً در `C:\SLTech\`:

* `net-push.ps1`
* `net-push.json`

محتوای `net-push.json`:

```json
{
  "url": "https://sltech.ir/api/kartabl/netuse/push",
  "key": "همان کلیدی که پنل داد",
  "range": "192.168.1.0/24",
  "community": "public",
  "timeoutMs": 500,
  "counters": { "192.168.1.1": [1] }
}
```

* `range` — هم `192.168.1.0/24` را می‌فهمد، هم `192.168.1.10-50`.
  **چند رنج** را هم می‌شود داد، با ویرگول یا به شکلِ فهرست:

  ```json
  "range": "10.170.10.0/24, 10.170.20.0/24",
  ```
  یا
  ```json
  "ranges": ["10.170.10.0/24", "10.170.20.0/24", "10.170.30.0/24"],
  ```

  هر رنج جدا گشته می‌شود و سقفِ هرکدام ۱۰۲۴ نشانی است.
  اول کلِ رنج با پینگِ دسته‌جمعی گشته می‌شود و فقط از نشانی‌هایی که
  جواب داده‌اند بقیهٔ سؤال‌ها پرسیده می‌شود — وگرنه یک /۲۴ چند دقیقه
  طول می‌کشید. دو نشانیِ اول و آخرِ هر رنج (جای همیشگیِ روتر) همیشه
  پرسیده می‌شوند، حتی اگر پینگ را بیندازند.
* `community` — جامعهٔ SNMP روتر. معمولاً `public`.
* `counters` — لازم نیست. خالی بگذارید (`"counters": {}`).

  هر دستگاهی که SNMP بدهد، پورت‌هایش خوانده می‌شود و پرکارترینِ آن‌ها
  — که تقریباً همیشه همان پورتِ اینترنت است — خودش برای مصرف انتخاب
  می‌شود. اگر در کارتابل روی «پورت» بزنید و پورتِ دیگری انتخاب کنید،
  اجرای بعدی همان را می‌خواند. این بند فقط برای وقتی است که بخواهید
  انتخاب را در خودِ فایل میخ کنید.

## ۳. یک بار دستی اجرا کنید

```powershell
powershell -ExecutionPolicy Bypass -File C:\SLTech\net-push.ps1
```

باید چیزی شبیه این بگوید:

```
Scanning 192.168.1.0/24 (254 addresses) ...
Found 23 device(s).
Read 1 counter(s).
Sent. kartabl says: {"ok":true,"hosts":23,"samples":1,"counted":0}
```

`counted:0` در اولین اجرا طبیعی است: مصرف از **تفاضلِ دو نمونه** درمی‌آید،
پس تا اجرای دوم عددی ثبت نمی‌شود.

## ۴. هر پنج دقیقه خودکار

در Task Scheduler یک کارِ تازه:

* **Trigger:** هر ۵ دقیقه، تکرارِ نامحدود.
* **Action:** `powershell.exe`
  با آرگومان: `-ExecutionPolicy Bypass -NoProfile -File C:\SLTech\net-push.ps1`
* **Run whether user is logged on or not** را بزنید.

پنج دقیقه عددِ دلبخواهی نیست: هرچه فاصله بیشتر باشد، ریستِ روتر بیشتر از
مصرفِ روز را می‌بلعد.

## اگر چیزی پیدا نشد

* از همان سیستم `ping 192.168.1.1` بگیرید. اگر جواب نمی‌دهد، رنج را
  اشتباه نوشته‌اید.
* اگر دستگاه‌ها پیدا می‌شوند ولی هیچ‌کدام SNMP ندارند، روی روتر SNMP را
  روشن کنید (نسخهٔ ۲c، فقط خواندن) و جامعه‌اش را در `net-push.json`
  بنویسید.
* ویندوزِ خودِ آن سیستم ممکن است پینگ را ببندد؛ اسکریپت به همین خاطر
  پورت‌ها را هم امتحان می‌کند و هر دو را با هم حساب می‌کند.

## چه چیزی فرستاده می‌شود

نشانی‌هایی که جواب داده‌اند، نامشان در DNS، پورت‌های بازِ شناخته‌شده،
آنچه خودِ دستگاه دربارهٔ خودش می‌گوید (SNMP)، و شمارندهٔ بایتِ پورت‌هایی که
خواسته‌اید. نه رمزی، نه نامِ کاربری، نه محتوایی.
